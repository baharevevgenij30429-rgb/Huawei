# Команда 521 — основа харнесса

Статус: стартовый прототип, не готовое финальное решение. Реальные API-запросы
не выполнялись. Docker-сборку нужно проверить при работающем Docker Desktop.

## Распределение работы

| Кто | Зона ответственности | Первый результат | Файлы |
| --- | --- | --- | --- |
| Участник 1 — инфраструктура | openJiuwen, API, Docker, инструменты, сохранение | Контейнер запускается в условиях жюри, одна задача решается через API | Dockerfile, JiuwenClient, execute_python, atomic_write |
| Участник 2 — стратегия | оценка расхода и выполнимости, выбор задач и модели | Сравнение baseline и нового планировщика на одинаковом бюджете | priority, token_cost, цикл run |
| Участник 3 — качество | собственный набор, проверяющий скрипт, траектории | Проверка 8 примеров без передачи expected агенту, затем собственный набор | test_baseline.py, будущие evaluate.py и datasets/ |

Если вас двое: первый берёт инфраструктуру, второй — стратегию и оценку;
проверку результатов делаете вместе. Перед совместными изменениями выделите
client.py, tools.py, planner.py из run_agent.py, чтобы не конфликтовать.

## Что уже есть

- Загрузка всех задач с белым списком полей: expected и check исключены.
- Начальный порядок reward / фиксированная оценка стоимости типа задачи.
- Реальные вызовы модели через openJiuwen Model, JSON-протокол действий.
- Выполнение Python, ограничение времени шага, короткий вывод инструментов.
- Лимиты шагов, общего времени, выходных токенов и локального бюджета.
- Атомарная запись ответа, статус submitted_unverified не означает прохождение тестов.
- Dry run без зависимостей, ключа и сетевых запросов.

## Быстрая проверка без API

Из папки проекта (Python 3.11):

```powershell
py -3.11 -m unittest -v test_baseline.py
py -3.11 run_agent.py --tasks-dir ./sample-tasks --dry-run
```

Примеры из исходного архива находятся в sample-tasks/ (локально, исключены из
git и Docker). Dry run только выводит порядок: задачи не решает и файлы не меняет.

## Сборка и запуск

Запустить Docker Desktop в режиме Linux containers, затем:

```powershell
docker build -t team521:baseline .
# Задайте LLM_BASE_URL и LLM_API_KEY в окружении своего терминала.
# Код приглашения не подставляйте вместо API-ключа.
docker run --rm --read-only --tmpfs /tmp:rw,size=2g --cap-drop ALL --security-opt no-new-privileges --cpus 4 --memory 16g --pids-limit 512 -e HOME=/tmp -e LLM_BASE_URL -e LLM_API_KEY -v "${PWD}/sample-tasks:/data/tasks:rw" team521:baseline --tasks-dir /data/tasks --budget 10000
```

10000 — наш тестовый лимит, НЕ объявленный бюджет соревнования. Секреты не
записывайте в репозиторий. .env.example — только образец: программа не загружает
.env автоматически. Для финальной проверки используйте сеть организаторов hack-net.
Обычный локальный docker run не воспроизводит ограничение сети соревнования.

Жюри может переопределить entrypoint и вызвать /app/run_agent.py напрямую.
По умолчанию ответ пишется в <task>/answer.txt. Для альтернативной трактовки
есть --answer-location workspace. Уточните официальный путь до сдачи.

## Следующие шаги команды

1. Уточнить путь answer.txt, бюджет и его передачу, точное время сдачи, CPU.
2. Получить настоящий API-ключ в кабинете. Проверить один короткий запрос:
   имена моделей, JSON, usage и включение reasoning в output_tokens.
3. Прогнать восемь примеров на копии набора, независимо проверить ответы и тесты.
4. Собирать траектории: task id, тип, модель, токены, длительность, результат.
5. Сделать собственные примеры, включая задачи с недостающими данными;
   отделить тренировочный набор от контрольного.
6. Настраивать оценки стоимости и stop-policy по измерениям, затем добавить
   переключение моделей и до пяти параллельных сессий с общим счётчиком бюджета.

## Известные ограничения

- Это один агент, без обученного оценщика и без специального распознавания
  невыполнимых задач. Приоритеты пока эвристические.
- Если usage отсутствует, списывается консервативный резерв; это не точный
  токенизатор. Формат usage SDK/прокси ещё не подтверждён. Общий лимит прокси
  остаётся окончательным ограничением. Reasoning по умолчанию считается уже
  включённым в completion_tokens — проверить на соревновании.
- Полная история пока растёт до лимита шагов. Дальше нужна компрессия контекста.
- Python-инструмент выполняет сгенерированный код. Удаление ключей из окружения
  дочернего процесса и системный промпт не являются песочницей. Запускайте живой
  агент только в изолированном контейнере без личных файлов. Между задачами пока
  нет отдельной файловой/сетевой изоляции, а таймаут убивает только прямой процесс.
- Тесты защищены инструкцией, а не правами файлов: нужна проверка неизменности
  тестов и усиление изоляции перед финальным прогоном.
- При ошибке API/протокола запуск останавливается, чтобы не повторять запросы
  с неизвестным расходом. Автовосстановление и проверка ответов — следующий этап.
- Закреплены версия Python-образа и openJiuwen. Транзитивные зависимости пока
  не зафиксированы lock-файлом: добавить после успешной сборки и замеров размера.
- Нельзя считать прототип прошедшим квалификацию до реального API-прогона.
